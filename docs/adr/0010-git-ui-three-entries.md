# Git UI 拆成三个职责分明的入口，提交面从「v1 不做」转正

ADR 0008 起了 git 的执行面，0009 把分支面收窄到 ZCode 的窄模型，两条都只回答了「在哪工作」。实跑后剩下的缺口是：**对话里改了文件，用户不知道该做什么**，得切到源代码管理页或者干脆开终端。本文记录两件事——UI 侧把 git 交互拆成三个入口，执行侧把提交面（改动列表 / 暂存 / 提交 / 推送）转正。依据是对 ZCode 源码的走查（`GitBranchSwitcher.tsx`、`GitActionMenu.tsx`、`v4/ConversationStatusPanel.tsx`）。

## Considered Options

- **做成一个大而全的 git 工具面板（否决）**：所有动作塞进一个入口，用户在「该改分支」的时刻要先翻菜单找到「该提交」那一栏。三个入口对应的是三个不同的决策时刻，混在一起每个时刻都要先翻菜单。
- **把三个入口合成两个（否决）**：分支切换与提交合并成一个「git 菜单」。丢掉的正是 ② 独立存在的价值——它的触发器是**状态信号**（有改动亮提交图标、领先远端亮推送图标），用户不点开就知道该做什么。合成进菜单后这个信号消失，只剩「进来之后自己找」。
- **三个入口各自独立（采纳）**：①「在哪工作」= 分支切换器（轻弹层，列表选一下）；②「要不要落库」= 状态驱动按钮 + 重对话框（填表单）；③「改了什么」= 文件列表 + diff 视图。轻弹层与重对话框是两种交互形态，不该互相迁就。

## Consequences

- **源代码管理页不是第四个入口，而是「仓库总管」**：它给的是分支 + 工作树 + 改动的全景，解决「坐下来管理这个仓库」；三个入口解决「聊天工作流中的高频动作」。会话工作树（隔离承重墙，ADR 0008）继续只住在这里。
- **提交面从 ADR 0008 的「v1 不做清单」移出**（只加方法，wire 协议是非破坏性演进，见 docs/07 §五）：`git.changes` / `git.diff` / `git.stage` / `git.unstage` / `git.commit` / `git.push` / `git.identity`，外加 `git.status` 的 `dirtyFileCount`。
- **提交面绑定激活单元的 rootPath（主工作树）**，与 BranchPicker 现行口径一致。会话工作树的改动状态是后续项（RPC 面天然可复用，传工作树路径即可）。
- **discard / 逐 hunk 暂存明确不做**：不可逆且无安全网，沿用 ADR 0009「checkpoint 路线推迟」的判断。stage 一律按**精确路径**不用 `.` —— 那会把并发执行器正在写的文件一并卷进索引。
- **`commit` 的默认语义是「只提交索引」**，不做隐式 `-a`。对话框勾「包含未暂存改动」时走另一条路：先 `add -A` 选中的路径再提交索引——未跟踪文件因此能进这次提交，且不波及其他路径。隐式 `-a` 会把 agent 刚写下的半成品文件一起提交掉。
- **新增 4 个错误码**：`nothing_to_commit` / `identity_missing` / `push_rejected`（`data.detail` 带远端原话）/ `no_remote`。词表唯一来源仍是 prototype/src/core/git.ts。身份缺失走预检（`git.identity` 返回 null）而不是等 git 抛英文多行报错，因为前者能给前端一条可操作的警告条。
- **push 的 remote 判定**：显式参数 → 已配置的 upstream → 仓库里唯一的 remote；都没有报 `no_remote`。多个远端又无法确定时同样报 `no_remote`，但文案说明原因——不硬造分类。
- **触发器「始终展示、异常时置灰，不消失」**：这是 ZCode 踩过的可用性坑——按钮消失了，用户不知道是仓库干净还是功能坏了。
- **AI 生成提交信息暂缓**：需要 daemon 侧模型调用面，三个选项（直连 provider / 借道执行器 CLI / 继续暂缓）实现时另开 ADR 定夺。
