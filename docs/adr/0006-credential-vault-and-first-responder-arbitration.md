# 凭证保险库与远程首响仲裁

微信等渠道扫码产出的动态访问凭证通过本地文件凭证保险库（Credential Vault）管理，杜绝明文写入 `bot.json`；远程多端审批接入工作台确认门，采用首响仲裁（First-Responder Arbitration）与全端广播失效机制。

## Considered Options

- **动态 Token 直写 `bot.json`（否决）**：`bot.json` 是工作空间或个人配置，易被版本管理误提交；工作台所有认证设计均坚持密钥不落共享配置。
- **强制手动配置环境变量（否决）**：扫码后要求用户手动打开终端设置环境变量并重启，严重违背微信扫码"一扫即连"的产品体验。
- **桌面独占审批（否决）**：移动端和 IM 只能旁观无法批准，导致人在床上或外出的远控场景彻底瘫痪。

## Consequences

- 动态获取的 `bot_token` 自动存入 `~/.agent-workbench/credentials/`，`bot.json` 仅落盘 `{ "source": "vault", "id": "..." }` 抽象引用。
- 确认门触发时向桌面、手机 Web 与各 IM 网关并发派发交互请求；任一端点击即完成仲裁，其余端通过事件流秒级收回或置灰，防止重复放行。
