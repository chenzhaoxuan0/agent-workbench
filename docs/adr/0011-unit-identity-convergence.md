# 单元身份收敛：统一零门槛创建、kind 降为弱标签、恢复双视图

左上角的"工作空间切换"继承自原开发工具（项目制、session 制场景），而本产品的实际场景是 personal agent（主 bot 用法、微开发用法），并已定调走向产品化分发。docs/00 立的北极星是「一套模型、两种视图」（数字员工模式 + 项目模式消费同一套 `WorkUnit` 原语），但前端把 `[bot|项目]` 分段切换器砍掉了（`Sidebar.tsx` 的 `VIEWS` 死代码），`kind: "project"` 自此休眠——docs/00 自己点破的「现有产品的前端只实现了一种身份模型」就是这么来的。本文记录把身份模型收拢回北极星、同时拆掉新建门槛的三个决策。

## Considered Options

- **切换器解构成"仅 bot 切换"（否决）**：确实最简，但砍掉了 docs/00 的双模北极星，而微开发用途是真实存在的（用户明确：最终开发仍回成熟工具，但本产品要兼容）。切换器事实上已经在切 bot（Composer 芯片 → ⌘K → `selectUnit`），"仅 bot"不是变更而是承认现状后封死另一半。
- **bot 体系 + 即席开发会话双体系（否决）**：即席会话 = 不注册单元、开个文件夹直接开会话。与「会话归属 bot，不归属端」（docs/09）正面冲突，等于把原开发工具的项目制/session 制混乱原样请回刚解构完的地方。
- **一套模型、两种视图（采纳）**：docs/00 原义。项目仍是注册制 `WorkUnit`，只是换项目视图消费；运行时原语（kind 字段、worktree、`session.rootPath`、SCM）全是现成的，恢复成本在 UI 层。

新建门槛与分型判据在同一棵决策树上：

- **三轨新建（轻量 bot / 专职 bot / 项目，首步三选一）（否决）**：三种单元三种入口，心智分叉，新用户第一步就要理解自己还没见过的分类学。
- **两条轻路径并存（起名即得 + 选文件夹）（否决）**：Q2 拍过"自动安置"，但它与"最简 = 选一个文件夹"不必是两个入口。
- **单轨零门槛（采纳）**：唯一必填交互 = 文件夹，且预填自动安置的默认位置——用户不动就是自动安置，改一下就是自定义指位，配系统文件夹选择器（不必复制粘贴路径）。现行 AddBotDialog 的必填链（AGENTS.md 等）拆除，AGENTS.md 从"必填的规矩"降级为可选增强。
- **git 自动推断项目（否决）**：本产品里 git 是文件版本管理基础设施，大量非开发 bot 的文件夹也用 git 管文件——"有 .git 就建议转项目"会把这批 bot 全部误判。
- **kind 参与运行时行为（否决）**：手动标错会产生功能后果（如隐藏人设编辑），与"分别不大"的定性矛盾。
- **kind 为弱标签、用户手动标（采纳）**：仅影响视图分组，不参与任何运行时行为。判据 = 产出物是否为软件工件（代码、diff、PR、构建产物），落成 3 秒能答的标注文案。

## Consequences

- **`[bot|项目]` 分段器复活为过滤器式**（`Sidebar.tsx:76-88` 死代码）：项目 tab 只显示手动标注 `kind: "project"` 的单元，bot tab 显示其余。留透镜式（同一批单元换布局侧重）的升级路——kind 既然是弱标签，升级透镜式数据零改动。项目视图最小版不建看板/diff/PR，直接复用现有源代码管理页、提交图、会话历史。
- **新建流拆除必填限制**：文件即数据库不破——无 AGENTS.md 的单元后台可静默生成最小占位，定义仍住单元自己的文件夹内。
- **文件夹输入带目录选择器（应用内目录浏览器）**：复用 `workspace.paths.list` RPC（与 @ 提及同一提供面、同一防逃逸约束）构建轻量目录浏览器，新建/认领的路径输入不再要求用户复制粘贴路径；Electron 阶段如需原生目录选择器可后替换同一交互位。
- **对外正名统一 bot / 项目**：清掉"工作空间 / Agent"字样（Composer 芯片"点击切换工作空间或 Agent"、Sidebar 标题 "Agent (N)"、⌘K 分组 "Agent 智能体"），代码内 `WorkUnit` 保留。docs/04「员工更名 bot」的既有决策照此执行到位。
- **存量单元不自动迁移**：编辑入口手动标 kind，包括本仓库自己的 `bot-agent-workbench`（实质是开发项目）。
- **产品化路线定序**：单机安装包为主线（现架构零改动压力），bot 分享为自然延伸（一个文件夹即一个 bot，天然可打包导入导出），云端多用户不预付任何架构成本。
- **onboarding 推迟到打包分发期**：daemon 已幂等生成 steward/heartbeat 两个内置 bot，零 bot 状态不存在；本次收敛的验收线 = 新装打开 steward 在、能零门槛新建 bot、能聊。
- **终端跟随、SCM、@ 提及继续挂在单元 rootPath 上**，存储模型（bot.json + AGENTS.md 住文件夹内）零改动。
