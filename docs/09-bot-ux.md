# 09 —— Bot UX 完整需求底稿：一个文件夹即一个 bot

> 本文回答三个问题：**bot 的使用逻辑到底是什么**；**这套逻辑落到界面上是什么形态**
> （生命周期、信息架构、渠道、记忆）；以及**「把已有文件夹认领为 bot」要补哪些东西**——
> 即 bot 区从「创建器」升级为「manager」的施工清单。
>
> 来源：2026-10-02 需求对齐对话。第一节保留需求原话与逐条落点，之后各节是对它的展开。

> 本文管 UX 形态（管理面）**，两者共享同一套领域模型（`core/units.ts`）。

## 〇、需求原话与逐条落点

需求方的完整陈述（2026-10-02）：

> 用户新建一个 bot，同时也新建一个文件夹，这个文件夹就作为这个 bot 的工作空间；
> 工作空间文件夹使用 AGENTS.md 来控制这个 bot 的最终行为。这个 bot 可以选择使用什么
> CLI 作为默认执行器，可以选择执行器中有的模型作为执行模型；可以选择被单独链接到
> 一个 IM 中作为机器人使用；可以选择所需了解的记忆（程序记忆 / 语义记忆 / 情景记忆）；
> 可以方便地在本机、IM、手机上调用。

另外一条补充需求（同日）：**当文件夹是老文件夹、内部结构已完整（AGENTS.md 等一应俱全）时，
应能把它作为 bot「认领」进来**——bot 区因此是一个 **bot manager**，而不是只能新建。

逐条对照现状（2026-10-02 时点）：

| # | 需求 | 契约落点 | 现状 | UX 缺口 |
|---|---|---|---|---|
| 1 | 新建 bot = 新建文件夹 = 工作空间 | `WorkUnit.rootPath`（`core/units.ts:87`，"一级身份就是文件夹"） | 已建模；`AddBotDialog` 四分区 | **快速创建路径**（30 秒版，见第三节） |
| 2 | AGENTS.md 控制 bot 最终行为 | `WorkspaceIdentity`（`core/units.ts:33`）+ "文件即数据库" | 已建模；创建时模板落盘的承诺在 `AddBotDialog` | **创建后的编辑投影**：外部改动检测、双向写回 |
| 3 | 选 CLI 作为默认执行器 | `RuntimeBinding.primary`（`core/units.ts:68`） | 已建模 | — |
| 4 | 选执行器中的模型 | `RuntimeBinding.modelHint`（"它是 hint 不是命令"） | 已建模 | **回落透明化**：hint 被静默忽略时用户无从知晓 |
| 5 | 单独链接到一个 IM | `BotChannel`（`core/units.ts:61`）+ daemon 渠道网关（docs/08 WP-8 ✅） | 契约与后端齐 | **渠道 UI 全缺**：前端 grep 不到 channels 的任何落点 |

| 7 | 本机 / IM / 手机调用 | daemon 多端客户端：LAN+鉴权（WP-7 ✅）、Telegram 网关（WP-8 ✅）、webhook/MCP（WP-9 ✅） | 后端齐 | **会话来源徽标**、跨端运行态可见 |

所有缺口集中在 UX 层。本文余下部分就是把右列变成施工单。

## 一、心智模型（先钉死）

一个 bot = **一个文件夹 + 一份岗位说明书（AGENTS.md）+ 一个默认执行器与模型
+ 几条找得到你的通道 + 一份会自己长大的记忆**。

用户和 bot 的关系只有两种时刻，UX 按这个切分，不按功能切分：

| 时刻 | 频率 | 深度 | 承载界面 |
|---|---|---|---|
| **养 bot**（配置与迭代） | 低频 | 深配置 | bot 详情页 / 编辑器 |
| **用 bot**（调用） | 高频 | 浅操作 | Composer / 手机 / IM |

八条需求各归一边：1-6 全是**养**，7 全是**用**。当前的问题精确说是：
「养」的动作被锁死在创建那一刻，之后养不动了。

---

## 二、使用逻辑（一句话版）

**用户在任意一端对 bot 说话 → bot 在自己的文件夹里干活 → 产出和记忆落回文件夹
→ 人随时从任意一端回来查账。**

两个推论直接决定 UI 形态：

1. **会话归属 bot，不归属端。** IM 里开始的会话在工作台能看到、能接续；手机上看到的
   和桌面是同一个东西。来源不同只体现在徽标上（"来自 Telegram" / "webhook" / "MCP"），
   不产生第二套会话体系。后端已是这个语义（单 bot 串行、续聊优先，docs/08 WP-8），UI 只欠来源标识。
2. **文件夹是唯一权威，UI 只是投影。** AGENTS.md、MEMORY.md、产出、`.agent-workbench/bot.json`
   全在 `rootPath` 下。UI 改配置 = 写文件；用户绕过 UI 手改了文件，UI 要能检测并提示
   "已在外部修改"。这是「文件即数据库」哲学的 UX 化，也是 docs/08"身份即文件，git 可管"
   差异点的界面兑现。

## 三、生命周期四幕

### 第一幕 · 创建（30 秒，不是四步）

现状：`AddBotDialog` 质量高（模板自动同步、AGENTS.md 与 SOUL 分离、三柱开关），
但它把**完整路径当成了唯一路径**——AGENTS.md 非空才能创建（`AddBotDialog.tsx:150`），
四分区都要过。这与 README 立的渐进披露哲学（"不用时不占版面，不是功能消失"）矛盾。

拆成两级：

- **快速路径（默认）**：只要「名字 + 一句话角色」→ 其余全默认：
  文件夹自动建、AGENTS.md 用现成模板落盘、执行器取当前默认、记忆跟随全局路由、不绑渠道。创建完立刻可聊。
- **完整路径（"高级配置"入口）**：即现在的四分区对话框，一字不动。

创建动作的本质在 UX 上要说清：**建文件夹 + 落 AGENTS.md + 写 bot.json，仅此三件事。**
底部文案从"创建后可随时改"改为"创建后的一切都在这个文件夹里"——把权威感交给文件夹。

### 第二幕 · 调用（四端同源）

| 端 | 现状 | UX 要点 |
|---|---|---|
| 工作台 Composer | ✅ | 主调用面，不动 |
| 手机浏览器 | ✅ WP-7（抽屉侧栏 + token 鉴权） | 就是响应式的同一个 app，不做第二套 UI |
| IM（Telegram） | ✅ WP-8（串行排队 / 续聊优先） | 我们不控制 IM 侧 UI；要补**回程**：IM 会话在工作台时间轴上有来源徽标，能点开看全程轨迹 |
| webhook / MCP | ✅ WP-9 | 同上，来源标 "webhook" / "MCP" |

bot 头像色形已按名字哈希稳定（`Sidebar.tsx:456` `botAvatarStyle`）——跨端身份一致性
的正确做法，四个端认同一张脸。

### 第三幕 · 成长（记忆——UX 缺口的另一半）

现状只有**配置时刻的一半**：创建时勾三柱、全局有后端注册表与路由（`useMemoryPrefs.ts`）。
但记忆的本质是**运行时长的**，缺运行后的三个动作：

- **查**：bot 详情页"记忆"分区按三柱分栏列出实际记住的内容（语义事实列表、
  情节摘要带日期、程序性技能文件）。MEMORY.md 镜像已是人读面，UI 渲染它即可。
- **改**：点一条语义事实直接编辑；程序性技能跳转 SKILL.md 编辑器。
- **忘**：单条删除。没有"忘"的记忆 UI 会让人不敢让 bot 记东西。

频率判断：**"审记忆"是比改配置更高频的养 bot 动作**——bot 跑了几天后，人回来第一件事
是看它学到了什么，而不是改执行器。所以记忆分区在详情页排位靠前。

### 第四幕 · 迭代（改行为 = 改文件）

AGENTS.md 是唯一权威。UX 原则：

- UI 里的编辑器直接写回 `rootPath/AGENTS.md`；
- 外部（VS Code、git）改了文件 → UI 显示"文件已在外部修改，点此重新加载"；
- 人设（SOUL）与岗位说明书（AGENTS.md）维持 waku 的分离，但展示上收进同一个"身份"分区。
  口诀已在 `AddBotDialog.tsx:22` 的注释里：**人设在 SOUL，规矩在 AGENTS.md**。

## 四、信息架构：bot 详情页

把 `AddBotDialog` 的四个分区**组件化后直接复用**为常驻的 bot 设置页，再补三个分区。
这是最关键的一步 UX 统一：**"新建"不是独立向导，而是配置面的空态首跑。**

```
bot 详情页
├── 身份        名称 / 角色 / 头像（自动色形）        ← 复用 AddBotDialog
├── AGENTS.md   岗位说明书 + SOUL 人设                ← 复用；外部修改检测
├── 执行器与模型  主执行器 + modelHint（回落要透明）    ← 复用
├── 记忆        三柱路由（跟随全局 / 覆盖）+ 查改忘    ← 复用开关 + 新增查看器
├── 渠道        IM / webhook 绑定向导                 ← 契约已有，UI 全缺
├── 日程        cron / 自动化（接入现有 AutomationsPage）
└── 产出        Deliverable 归档（按会话回看）
```

入口分离：侧栏 bot 行点击 = 进会话（高频、用）；`openUnitSettings`（`useShell.ts:215`，
`UnitRow` 上已有挂点 `Sidebar.tsx:288`）= 进详情页（低频、养）。两个入口互不打扰。

编辑态骨架已埋好：`editUnitId` 状态与对话框复用（`Sidebar.tsx:113-118`），
本节要做的只是把"对话框"升级为"详情页"，并让 daemon 扫描来的单元也走同一条编辑路径。

## 五、渠道绑定 UX（缺失的最大一块）

`WorkUnit.channels` 契约已在（`core/units.ts:116`），前端零落点。绑定向导四步，
**风险声明必须在绑定时刻，不能藏在设置里**：

1. 选渠道（Telegram / Discord / webhook）；
2. 填 token——保存后永久遮蔽显示。bot.json 明文是本机私有文件的预期
   （`core/units.ts:58` 注释），但 UI 永不再回显；
3. 发一条测试消息验证连通；
4. **权限声明卡**："这个 bot 在 IM 里是 headless 的，没有逐条审批面，将按
   【当前档位 yolo】自动执行。"（docs/08 已定死：IM 权限档固定 yolo，收权靠预置规则表。）
   给两个出口：接受；或先去配预置规则再开。

绑定成功后渠道在详情页显示状态徽标（已连接 / 已停用），侧栏 bot 行给一枚极小的渠道图标——
"这个 bot 找得到我"这个事实应当一眼可见。

## 六、透明化三细节（小但重要）

1. **modelHint 静默回落**：契约写明 hint 指向不接的模型会被静默忽略。UX 必须补回这个
   "静默"——会话头部显示实际生效的模型，hint 失效给弱提示，否则用户以为自己在用便宜模型。
2. **IM 会话进行中的跨端可见**：bot 正在 IM 里干活时，工作台侧栏该 bot 行应有运行态指示
   （`SessionStatus` 已有，接上即可），避免"两个我在同时使唤一个 bot"的冲突感。
3. **"完全放行"警示色机制**（已实现）推广到所有 headless 场景：IM 绑定、webhook 暴露——
   凡是"以后不再问"的开关，一律常驻警示。

## 七、导入已有文件夹：bot 区升级为 manager

### 7.0 概念（先钉死）

**导入 = 注册，不是移动。** 这是「文件即数据库」的自然延伸：

> 新建 = 建文件夹 + 写 AGENTS.md + 注册；**导入 = 只注册**。

文件夹留在原地，git 历史不动，workbench 只是把它登记进管理面。这句话直接写进
导入对话框副标题。导入完成后 daemon 立刻拿到完整定义（执行器/模型/记忆路由/渠道/日程），
**IM、webhook、cron 全部即时激活**——这就是 bot manager 形态的兑现：
bot 区 = 注册表，能力集 = 新建 + 认领 +（将来）移出管理（detach ≠ delete，见 7.4）。

### 7.1 现状盘点（后端几乎免费）

- `BotRegistry.putBot()`（`backend/src/bots/registry.ts:60`）本就接受任何已存在目录：
  写 `<rootPath>/.agent-workbench/bot.json` + 把父目录登记为扫描根（72-73 行），
  老文件夹原地不动即被纳管；"目录必须存在"校验（65 行）对导入场景刚好是对的。
- 扫描语义：`listBots()`（`registry.ts:86`）扫全部根目录**下一层**子目录，
  读 `.agent-workbench/bot.json`，按 id 去重、channels 脏数据容错（103-107 行）。
- 前端写穿管道已在：`putBotDefinition` / `listBotDefinitions`
  （`adapters/daemon/client.ts:290,296`）；RPC `bot.put` / `bot.list` / `bot.roots.add`
  （`backend/src/index.ts:406-414`）。

### 7.2 缺口清单

**后端（S，约一天）**

1. **新增 `bot.inspect(rootPath)` RPC**（纯读、不落盘）——导入流程的地基，返回探测报告：

   | 探测项 | 用途 |
   |---|---|
   | 目录存在 / 是否 git 仓库 | 基础校验 |
   | AGENTS.md 是否存在 | 决定导入三分支（7.3） |
   | 从 AGENTS.md 派生的名称/角色候选 | 预填表单。**目前全仓库没有任何代码构造 `WorkspaceIdentity`**，需写一个小派生函数：首个一级标题 → name，引言行 → role |
   | `.agent-workbench/bot.json` 是否已存在 | 存在 = "重新连接"而非"导入"，返回其定义 |
   | 资产盘点：SKILL.md / skills 目录 / MEMORY.md / 已有 automations | 让用户看见"这个文件夹里已有什么会被继承" |
   | 冲突：路径已被注册？嵌在另一个 bot 的 rootPath 内？ | 导入前拦截 |
   | 扫描根副作用：父目录成为扫描根后，同级还有几个 bot.json 会被一并扫出 | 导入 `D:\work\old-repo` 会让 `D:\work` 下其他已配置 bot 一并出现——设计使然，但必须让用户事先看见 |
   | **是 git 仓库且 `.agent-workbench/` 未被 ignore** | 安全项，见 7.5 |

2. **加固 `putBot`**：同 rootPath 重复注册拒绝；rootPath 嵌套在已注册 bot 内部时警告。
3. 派生命名权威顺序：**bot.json > AGENTS.md 标题 > 文件夹名**，预填按此回退。

**契约（零改动）**

`WorkUnit` 不缺任何字段。来源标记用现成 `tags`（创建打 `["新建"]`，导入打 `["导入"]`），不动 schema。

**前端（M，2-3 天）**

1. **入口**：侧栏添加区现为「添加 bot / 添加项目」二选一（`Sidebar.tsx:282` 附近），
   加第三项「**添加已有文件夹**」。
2. **导入对话框**（新组件，与 `AddBotDialog` 平级）：输入路径（现阶段文本框，
   Electron 阶段换 file dialog）→ 调 `bot.inspect` → 按探测结果走三分支。
3. **写穿**：认领与后续编辑走 `bot.put`；启动合并管道已有，导入的 bot 与新建的 bot
   走同一条编辑路径，不设第二套。

### 7.3 导入对话框：三分支

| 分支 | 触发条件（inspect 结果） | 交互 | 写盘动作 |
|---|---|---|---|
| **重新连接** | 已有 bot.json | 展示既有定义让用户确认；场景：换浏览器 / 换机器后重新纳管 | 零写入 |
| **认领**（主路径） | 有 AGENTS.md、无 bot.json | 用派生结果预填名称/角色，用户补选执行器、模型、记忆路由 | `putBot` 落盘 bot.json |
| **脚手架** | 两者皆无 | 问用户"要不要按模板补一份 AGENTS.md 再注册"，或建议以 project 身份导入。**不能静默替老文件夹做决定** | 用户确认后写模板 + bot.json |

表单复用 `AddBotDialog` 的"身份"分区组件——第四节的分区组件化在这里顺手兑现：
**组件化一次，创建、编辑、导入三个面全齐。**

### 7.4 边界情况清单（实现时对照）

- 老文件夹直接在盘符根下：`putBot` 已有 warn（`registry.ts:77`，根目录不可扫描），
  inspect 报告前置提醒"移到子目录才能被扫描到"。
- 嵌套导入（子目录再注册成 bot）：后端警告 + 文档写明语义。
- 同路径重复：拒绝并提示已有 unit id。
- 网络盘 / 已删除路径：落"目录不可用"徽标——`UNAVAILABLE_UNIT` 先例已在侧栏（`Sidebar.tsx:124`）。
- 将来：`bot.forget`（移出管理不删文件夹）。manager 的完整闭环 = 新建 + 认领 + 移出，
  原型期后置，契约上留位置。

### 7.5 一个必须做的安全检查：git + token

`core/units.ts:58` 写明 bot.json 里会有渠道敏感值，且预期"不是要提交的仓库资产"。
但本需求的场景恰好是**老文件夹 = 大概率是 git 仓库**：导入一个绑了 Telegram token 的
bot.json 进 git 仓库，用户一 push，token 即泄漏。

因此 `bot.inspect` 必须报"是 git 仓库且 `.agent-workbench/` 不在 ignore 里"，
导入对话框在落盘前给硬提示，并提供一键补 `.gitignore`。**这条是导入功能的安全前提，
不是锦上添花。**

## 八、落地顺序

| 阶段 | 内容 | 规模 | 验收口径 |
|---|---|---|---|
| **P0-A** | `AddBotDialog` 分区组件化；bot 详情页（编辑态收尾，含 SOUL/AGENTS 双编辑与外部修改检测）；快速创建路径 | M | 只填名字+角色可创建成功，落盘三件事齐全；详情页七分区可改、改完 `bot.json` diff 可见 |
| **P0-B** | `bot.inspect` RPC（含 AGENTS.md 派生、冲突、git/token 检查）；`putBot` 两处校验 | S | 对三种老文件夹（全齐 / 仅 AGENTS.md / 空目录）探测报告各字段正确；重复与嵌套被拦 |
| **P1-A** | 导入对话框三分支 + 侧栏入口 + `.gitignore` 一键补 | M | 认领一个真实老仓库 → 关浏览器、清 localStorage、重启 daemon → bot 仍在、IM 可触发；push 前 token 不入库 |
| **P1-B** | 渠道绑定向导；IM/webhook/MCP 会话来源徽标；跨端运行态；modelHint 回落透明化 | M | Telegram 里跑的会话在工作台时间轴可见且可点开；hint 指向不可用模型时界面如实显示实际模型 |
| **P2** | 记忆查看器（查/改/忘）；`bot.forget` | M | 三柱分栏可读可删；移出管理后文件夹与 bot.json 原样保留 |

顺序依据：P0-A 的分区组件化是 P1-A 导入表单的前置；P0-B 先行让前端对话框拿真探测数据开发。

## 九、不做清单

- **导入不搬家**：不做"复制文件夹进 bots 目录"的选项——注册语义下它是伪需求。
- **不做 AGENTS.md frontmatter 机器配置**：机器配置只进 bot.json（`registry.ts:8-9`
  的形态决策，AGENTS.md 是给人看的，承诺不破）。
- **手机不做原生 App**：浏览器/PWA 即可（docs/08 已定）。
- **多用户、云同步**：维持 docs/08 不做清单。
- **不在导入时自动改老仓库的任何既有文件**：唯一的写盘例外是新增 `.agent-workbench/`
  与（用户确认的）`.gitignore` 追加。

## 十、灵魂一句话

> **bot 的一切都活在它的文件夹里：工作台是投影，四个端是窗口，养和用分开走；
> 管理面的能力集是"新建、认领、迭代"，而认领让老文件夹第一次成为一等公民。**
